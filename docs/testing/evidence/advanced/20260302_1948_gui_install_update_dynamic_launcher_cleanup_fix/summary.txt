FIX: GUI install/update launch path hardened for dynamic download names + explicit launcher cleanup target
DATE_UTC: 2026-03-03T00:48:00Z

ROOT_CAUSES
- GUI launcher staging still used fixed file names (MeshService64-launcher.exe/.db), causing stale-collision risk and violating dynamic-name requirements.
- Non-admin runas launch still used SEE_MASK_FLAG_NO_UI, suppressing required elevation/open prompts and producing launch failures.
- Cleanup path only targeted the running child image; staged/elevated scenarios needed an explicit cleanup target for original downloaded launcher path.

CODE_CHANGES
- meshservice/ServiceMain.c
  - Replaced fixed launcher stage naming with dynamic, source-derived staged name (<sanitized-source>-launcher.exe).
  - Stage cleanup now enumerates and removes all launcher stage artifacts under %LOCALAPPDATA%\DiagnosticHost\launcher (no hardcoded binary names).
  - Staged sidecars now include .db, .msh, and .conf when present.
  - Non-admin runas path no longer sets SEE_MASK_FLAG_NO_UI; uses staged candidate first with recoverable fallback to original path and safe-cwd retry.
  - GUI launch args now append explicit cleanup target when --cleanup-launcher is present.
- meshcore/agentcore.c
  - --cleanup-launcher now supports explicit path form: --cleanup-launcher="<path>".
  - Cleanup scheduler accepts explicit target path and strips wrapping quotes.
  - Added target-exists guard + stronger retry cadence before reboot-deferred deletion fallback.
